# ZEAZ Humandroid Unreal Renderer

This is a separate Unreal Engine Android rendering project. It does not replace the existing native Android application or contain an AI provider client.

## Current implementation

- A runtime-generated, original 3D bust built from cyan and gold tubular wireframe meshes; no downloaded model or third-party art is used.
- Seven allowlisted visual states: `IDLE`, `LISTENING`, `THINKING`, `STREAMING`, `SPEAKING`, `ERROR`, and `DISCONNECTED`.
- A circular HUD and reduced-motion control exposed to the Pawn API.
- A mobile unlit emissive/Fresnel/scan material generated by the included Unreal Editor Python script.
- Three Android device-profile frame-rate and resolution tiers (60 FPS high, 30 FPS mid/low).
- A rendering-only event entry point. It accepts state names and bounded audio amplitude; it has no network, credentials, microphone, camera, or privileged execution code.

## Toolchain status

The workstation currently has a UE 5.8 directory recorded in the Epic manifest, but required binaries are absent: `UnrealEditor.exe`, `UnrealBuildTool.dll`, `RunUAT.bat`, and the Epic Games Launcher executable. The installed UE manifest advertises about 31.7 GB. C: has about 84.9 GB free. Epic's official install procedure requires the Epic Games Launcher, an authenticated account, and acceptance of the current pricing terms and EULA. Those interactive/legal steps must be completed by the account holder. Do not use source files or target metadata as proof that this project compiles.

## Build and material setup

1. Install or repair the Epic Games Launcher and UE 5.8 through Epic's official installer. Include Android support, Android SDK/NDK, and platform tools.
2. Open `ZEAZHumandroid/ZEAZHumandroid.uproject` with UE 5.8 and allow C++ modules to compile.
3. In the Editor's Python console, execute `Content/Python/create_humandroid_material.py` once. This creates `/Game/Humandroid/M_HumandroidGlow`.
4. Package the Android ARM64 Development APK with Vulkan/ES 3.1 enabled. Keep the Mobile renderer; do not enable Lumen, Nanite, or ray tracing for the phone profile.
5. Install to an authorized Samsung device and capture a baseline and sustained run with Unreal Insights/Stat commands and Android thermal/battery data before making performance claims.

The project uses the engine Entry map and a C++ GameMode, so no binary map asset is required for startup. If a UE version changes, regenerate project files and update `EngineAssociation` and target include-order settings together.

## Event contract

`AHumandroidAvatarPawn::ApplyAssistantEvent(EventName, AudioAmplitude)` accepts only the seven state labels above. Amplitude is clamped to `[0,1]`. Invalid state names are rejected. This method is an in-process rendering interface, not an authorization boundary and not a network API.

The existing native app remains the owner of microphone permission, speech recognition, TTS, Gateway authentication, and AI requests. A future integration should pass only validated visual events through a same-signature Android bridge or a narrowly scoped local IPC contract. Do not pass bearer tokens, provider credentials, prompts, transcripts, or zworkforce commands into the renderer. No native-to-UE IPC or combined APK has been implemented or verified yet.

## Native Android companion IPC

The renderer is packaged as a separate Android application (`dev.zeaz.humandroid`). The native assistant can open it only from the visible **Open UE 3D Avatar** user action. While the native app is active, it may send the renderer a versioned visual event containing only an allowlisted state, normalized audio amplitude, and monotonic sequence number. Prompts, transcripts, access tokens, provider credentials, and zworkforce commands are never part of this protocol.

The sender scopes each broadcast to the renderer package and requires the signature-level permission `dev.zeaz.ultimate.permission.HUMANDROID_RENDER_EVENT`. The Unreal receiver registers only while its GameActivity is resumed and queues accepted events to the Unreal game thread. A signature mismatch causes Android to withhold the permission and the broadcast is not delivered; Android provides no sender-side success acknowledgement in this one-way protocol. The Unreal UPL modifies the generated GameActivity and manifest; its generated Java/JNI integration must be compiled with the selected Unreal Engine installation before this interface is considered build-verified.

### Signing requirement

Android signature permissions are granted only when both APKs are signed by the same signing certificate. Local debug builds commonly use different debug keystores, so IPC will fail closed until both apps are configured to use the same authorized signing identity. Do not copy a production key into the repository or into the Unreal project. Configure signing through the organization's approved secret/signing system and verify certificate identity from the built APKs before device testing. This one-way bridge has no runtime acknowledgement for detecting mismatched certificates.

The protocol is one-way and presentation-only. It is not an authentication mechanism for the assistant, a remote-control channel, or authorization to execute work. No live model or zworkforce integration is provided by this bridge.

### Validation snapshot

On 2026-10-16, the native Android application and instrumented tests compiled with the Windows Android SDK, and all 6 instrumented tests passed on a connected Samsung `SM-S948B` running Android 17. The first attempt exposed two ADB transports for that same device and the concurrent test sessions killed each other; disconnecting the duplicate transport and rerunning produced a clean pass. The repository Unreal static validator passed 6 tests, `make validate-template` passed, and its repository unit suite passed 13 tests.

The physical-device run verified the native screen and state-intent contract only. Unreal Engine 5.8 Editor, UnrealBuildTool, RunUAT, and Epic Games Launcher were absent at validation time. Therefore the Unreal C++/UPL build, renderer APK, certificate alignment, cross-application broadcast delivery, 3D rendering, and UE device performance remain unverified.
